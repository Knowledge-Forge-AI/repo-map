## Preparation-worker diagnosis and bounded fixture correction

Both integration failures occurred after a valid terminal receipt, at the
300ms natural-exit join. The saved failures do not distinguish a still-live
process from nonzero exit. Coverage finalization is a plausible contributor,
not a proven unique cause. Preserve that uncertainty and add bounded diagnostic
facts for process liveness, exit code and cleanup duration to fixture refusals.
Keep the production worker byte-identical to its accepted source. A fixture
subclass observes its existing cleanup entry and attaches facts to the original
exception; it delegates cleanup unchanged. The pinned dynamic-target registry
and all of its historical records remain unchanged.

The synthetic successful preparation fixtures should allow800ms for natural
process settlement, reduce their attempt bound3400ms to2900ms, and use the
mechanically derived9900ms two-attempt envelope. This stays below the existing
10-second architecture cap; production defaults, policy validators, semantic
operation clocks and cleanup refusal rules do not change. A synthetic delayed
interpreter exit exercises successful settlement inside the selected allowance;
the inherited over-limit refusal and cleanup rules remain unchanged. This is an individual
fixture correction, not a coverage exemption or runner-policy change.

Independent source review recommended a350ms deliberate exit delay so the800ms
settlement allowance retains450ms for coverage finalization and other exit
handlers. This is a bounded positive regression; local proof has no coverage
and does not establish a unique historical cause or a covered runtime margin.
Fixture observation errors are captured without bypassing cleanup, with state
before and after cleanup. Ordinary success/failure/crash cases in the
preparation-worker integration file retain the unwrapped production attempt;
a separate failure case checks diagnostic notes. The shared H08 helper uses
the observing fixture subclass.
