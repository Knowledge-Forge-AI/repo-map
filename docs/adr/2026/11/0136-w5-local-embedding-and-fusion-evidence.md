## Why this candidate

The upstream [BGE model card](https://huggingface.co/BAAI/bge-small-en-v1.5)
describes an English 384-dimensional model with 512-token inputs and an ONNX
artifact; its license section identifies MIT licensing. These characteristics
fit a bounded CPU comparison over the current English calibration fixture.
They do not predict quality on CLOE tasks. Input formatting, query instruction,
CLS pooling, normalization and truncation must be versioned and verified against
the acquired graph before generating evidence.

[ONNX Runtime](https://onnxruntime.ai/docs/get-started/with-python.html) provides
the CPU execution API. Its
[versioned license](https://raw.githubusercontent.com/microsoft/onnxruntime/v1.31.1/LICENSE)
is MIT; [Tokenizers 0.23.3](https://raw.githubusercontent.com/huggingface/tokenizers/v0.23.3/LICENSE)
uses Apache 2.0. That does not settle licenses or native-library notices inside
the full wheels. Those remain a pre-execution gate. No claim of absence of
vulnerabilities or packaging compatibility follows from package metadata.

## Three connected epics

1. **Verified local enrichment artifacts.** Add explicit public-fixture input,

   immutable outputs, bounded diagnostics and cleanup. Preserve existing

   first milestone embeds those accepted node metadata bytes, not body chunks.
   A captured-chunk representation/storage extension remains a later decision.
2. **Vector and fusion comparison.** Extend the current evaluator with actual
   exact pgvector, a disposable HNSW candidate and an explicit rank-fusion
   experiment against the same current lexical/graph/native baselines. Fusion
   is explicitly file-level: map actual accepted evidence to binding/snapshot/
   relative-path identities, with per-arm provenance and separate node metrics.
   Missing arms remain unavailable; no silent lexical fallback or fabricated
   semantic observation is permitted. No similarity creates a canonical edge.
3. **Named JSONB workload disposition.** Measure node-evidence expansion by
   publication and canonical key, and only a concrete derived-search facet
   where justified, against relational joins and disposable jsonb_ops/
   jsonb_path_ops alternatives only in disposable databases. The named facet
   uses existing binding/snapshot metadata; vary only the approved fixture
   publications, without a synthetic multiplier or new corpus, and report the
   tiny scale. Keep identity and integrity relational. Retain plans,
   row/selectivity, correctness, cost and failure observations. Adoption
   is not predetermined; retaining the relational design is a valid result.

These epics target one substantial reviewed milestone. Line-count batching is
not permission to add filler. Do not publish an intermediate docs-only or
synthetic-mechanics update as W5 usefulness.

## Canonical confidence compatibility correction

Native calibration exposed a mismatch in the evaluator's candidate parser.
The maintained PostgreSQL schema stores node and evidence confidence as the
text enums `manual`, `extracted`, `heuristic` and `unknown`. Both exact and
HNSW SQL preserve those values. The new evaluator incorrectly required numeric
confidence, so it rejected valid exact-baseline rows before native plan work.

The evaluator must validate the existing enum at both candidate and evidence
boundaries, rejecting numeric, unknown and non-text values. Preserve all other
shape, identity, privacy, finite-distance, scope and ordering checks. Confidence
does not become a relevance score, ranking weight or numeric conversion. This
corrects the evaluator to the established graph contract; it changes neither
canonical storage nor production extraction/query behavior. Unit boundaries
and a disposable PostgreSQL serialization regression must precede another
native calibration attempt. Earlier failed evidence remains failed history.
