# REPOMAP-CLOE-INSTALL1 Exit

## Scope and boundary

ADR0121 adds explicit read-only installation metadata diagnostics and persisted
native service-module compatibility as a two-part W1 upgrade prerequisite.
`identity --installation-check` has its own versioned categorical payload and
exit semantics; ordinary identity JSON retains its exact six keys. Metadata
evidence does not qualify a wheel, installer, entrypoint or runtime. Source
checkouts without metadata are unverified, not healthy installations.

Service generation uses the current import owner. Exact v1 native definitions
can be classified as current, legacy or unrecognized without broadening their
closed shape or ownership checks. Legacy status requires reinstallation and
does not probe readiness; execution/upgrade refuses it. Explicit legacy uninstall
never enables or starts the old module, even when failure requires file recovery.
Malformed launchd XML is a refusal rather than an uncaught parser exception.

Current distribution/import/commands/resources and all durable identities remain
unchanged. Simulated future-module tests do not claim a renamed installation or
live native-service qualification. The actual atomic package cutover, disposable
install-order proof and exact retained-history module-path projection remain
subsequent W1 work. The documented config-migration Python API is retained as a
real consumer decision; the advisory no-library-facades conclusion was rejected.
